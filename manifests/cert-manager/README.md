# manifests/cert-manager

TLS via cert-manager + Let's Encrypt (ADR D5). Synced by the `cert-manager`
Argo Application (`gitops/apps/cert-manager.yaml`, sync-wave 0). The operator
Subscription is bootstrap-applied from `gitops/operators/10-cert-manager.yaml`.

| File | Purpose |
|------|---------|
| `cluster-issuer.yaml` | `ClusterIssuer` `letsencrypt-prod` + `letsencrypt-staging` (ACME, **Route53 dns01**). |
| `certmanager-dns01-nameservers.yaml` | Points the operator-managed controller's DNS-01 checks at public resolvers (the IPI private `cluster.<domain>` zone otherwise hides the public one). |
| `apps-wildcard-certificate.yaml` | Wildcard `Certificate` (`*.apps…` + `*.coder.apps…`) → Secret `apps-wildcard-cert` in `openshift-ingress`. |
| `ingresscontroller-default-cert.yaml` | Sets that wildcard as the IngressController `defaultCertificate` + allows wildcard Routes for Coder workspace apps (scoped SSA, `Prune=false`; the only manifest for this object). |

## How TLS is delivered
The RH cert-manager operator does **not** reconcile OpenShift `Route` objects, so
per-route `cert-manager.io/*` annotations are no-ops. Instead we issue one
wildcard cert and set it as the **router default** — every edge-terminated Route
(keycloak, coder, gitea, the GitOps console `openshift-gitops-server`, and
Coder workspace-app subdomains) then serves a valid cert automatically, with no
per-route wiring.

> Note: some earlier Route manifests still carry legacy `cert-manager.io/*`
> annotations; they are harmless (inert) and can be removed in a later tidy-up.

## Deploy-time requirement (IRSA, not committed — D5)
dns01 needs AWS Route53 access. Annotate the cert-manager controller
ServiceAccount at deploy time (terraform output; via `task`/env, never in git):

```
oc annotate sa cert-manager -n cert-manager \
  eks.amazonaws.com/role-arn=arn:aws:iam::<AWS_ACCOUNT_ID>:role/<cluster>-cert-manager-route53
```

The issuers carry no credentials; the ACME account keys are generated by
cert-manager. Use `letsencrypt-staging` while iterating to avoid the prod
Let's Encrypt rate limit, then switch the Certificate's `issuerRef` to prod.

**Validated:** cert-manager operator (v1.20) + the live `letsencrypt-prod`
dns01 issuer and `apps-wildcard-cert`/defaultCertificate pattern were confirmed
on the running cluster; CRD schemas are `cert-manager.io/v1`.
